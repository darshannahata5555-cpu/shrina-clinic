# SHRINA Clinic — engineering conventions

Internal clinic-management app for SHRINA Korean Beauty Aesthetic Clinic. Multi-branch, role-based.
Stack: **Next.js 16 (App Router, Turbopack, React 19) · TypeScript · Tailwind CSS v4 · Prisma 6 · PostgreSQL**.
Cache Components are **off**: every page is request-time dynamic (no `"use cache"`, no Suspense requirements).

> Next 16 notes: `params`, `searchParams`, `cookies()`, `headers()` are **async** (`await`). Middleware is
> `src/proxy.ts`. Page props type: `PageProps<"/patients/[id]">`; route handlers: `RouteContext<"/api/x/[id]">`
> (generated by `npx next typegen`). Docs: `node_modules/next/dist/docs/`.

## Running

- Dev server: `npm run dev` → http://localhost:4600 (one shared server is usually already running — don't start another).
- Typecheck: `npx tsc --noEmit` (run `npx next typegen` first if you add routes and PageProps types are missing).
- Reset demo data: `npm run db:seed` (wipes everything). Demo logins: `owner@ / manager@ / doctor@ / reception@ /
  therapist@ / accounts@ / hr@shrina.in`, password `Shrina@123`. Staff attendance PIN for all seeded staff: `1234`.
- Check a page as a user without a browser:
  `COOKIE=$(npx tsx scripts/dev-cookie.ts reception@shrina.in); curl -s -b "$COOKIE" http://localhost:4600/patients -o /tmp/p.html -w "%{http_code}\n"`
  (a 307 to `/forbidden` means the role lacks permission; a 500 means a server error — see the dev-server log).

## Rules every module follows

1. **Permissions.** Every page calls `requirePermission(...)` (or `requireUser()` + checks). Every server action starts with
   `assertPermission(...)`. Hide buttons the user can't use with `can(user, perm)`. Confidential medical fields
   (`Patient.medicalHistory`, `Consultation.doctorNotes`, `MedicalHistoryEntry`) only render with `patients.medical`.
2. **Branch scoping.** Every list/aggregate query filters `branchId: { in: scope.ids }` (from `getBranchScope()`).
   Every mutation on an existing record verifies `assertBranchAccess(user, record.branchId)`. New records get their
   branch from a form `branchId` select (show it when `scope.isAll` or the user has >1 branch) via `resolveWriteBranch`.
   When `scope.isAll`, show a branch column/badge in tables.
3. **Server actions** live in `actions.ts` with `"use server"`, signature `(prev: ActionState, fd: FormData) => Promise<ActionState>`,
   body wrapped in `handle(async () => { … })`. Validate with zod via `parse(schema, formObject(fd))` and `zf.*` helpers.
   Multi-step writes go in `db.$transaction(async (tx) => { … })` and pass `tx` to lib helpers. Return
   `{ ok: true, message: "…", id }`. To navigate after create, call `redirect()` (it's re-thrown by `handle`).
4. **Audit.** Every create / update / delete / approve / reject / status change / payment / refund / export calls `audit(...)`
   with a human summary ("Cancelled invoice FLG/2526/0042 — duplicate billing") and, for updates, `changes: diff(before, after, keys)`.
5. **Soft delete.** Never hard-delete business records: set `deletedAt = new Date()` and filter `deletedAt: null` in every query.
   (Settings → Recycle bin restores them.)
6. **Money & dates.** Prisma `Decimal` → `toNum()` before maths; round with `r2()`; display with `money()`. All dates are
   shown and entered in IST: `<input type="date">` values via `toIstDateInput`/`zf.date()`, `datetime-local` via
   `toIstLocalInput`/`zf.dateTime()`. "Today" = `istDayRange()`. `@db.Date` columns use `dbDate("YYYY-MM-DD")`.
7. **Passing data to client components:** convert `Decimal` → number and keep props serialisable (Dates are fine).

## UI conventions

- Look: calm, minimal, professional; warm neutral surfaces, rosewood accent (`bg-accent`, `text-accent`, `bg-accent-soft`).
  Use tokens only — `bg-surface`, `bg-surface-2`, `bg-surface-3`, `border-border`, `text-ink`, `text-ink-2`, `text-muted`,
  `text-success|warning|danger|info|violet` and their `-soft` backgrounds. **Never hard-code colours** (dark mode must work).
- Page skeleton: `<PageHeader title description actions back />` → `<Card>` blocks. Filters go in one row above the table
  (`FilterBar` + `SearchParamInput`, `SelectParam`, `DateParam`, `SegmentParam` — they write URL search params).
  Tabs: `<LinkTabs>` (state in URL `?tab=`). Lists paginate with `<Pagination>` (25/page).
- Forms: client component using `<ActionForm action={…}>{(s) => …}</ActionForm>` with `<Field label error={fe(s,"name")}>`,
  `Input/Select/Textarea/Checkbox`, `<SubmitButton pendingText>`. Small forms in `<Dialog>`; big ones on their own page.
  One-click actions: `<ActionButton action fields confirm>`.
- Status pills: `<StatusBadge kind="appointment" status={a.status} />`. KPI tiles: `<StatCard>`. Empty lists: `<EmptyState>`.
- Tables: `<Table><THead><tr><TH/></tr></THead><tbody><TR><TD/></TR></tbody></Table>`; numbers right-aligned with `tabular`.
- Mobile: everything must work at 375px — hide secondary columns with `hidden md:table-cell`, stack grids.
- Copy: plain words for non-technical staff ("Mark session done", not "Commit session"). Sentence case.
- Charts: follow the `dataviz` guidance (thin bars ≤24px, 4px rounded ends, hairline solid grid, legend for ≥2 series,
  hover tooltip, text never in series colour). See `src/components/charts/simple-bar-chart.tsx`.
